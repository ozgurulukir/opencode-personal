Use the `apply_patch` tool to edit files. Your patch language is a stripped‑down, file‑oriented diff format designed to be easy to parse and safe to apply. You can think of it as a high‑level envelope:

*** Begin Patch
[ one or more file sections ]
*** End Patch

Within that envelope, you get a sequence of file operations.
You MUST include a header to specify the action you are taking.
Each operation starts with one of three headers:

*** Add File: <path> - create a new file. Every following line is a + line (the initial contents).
*** Delete File: <path> - remove an existing file. Nothing follows.
*** Update File: <path> - patch an existing file in place (optionally with a rename).

Example patch:

```
*** Begin Patch
*** Add File: hello.txt
+Hello world
*** Update File: src/app.py
*** Move to: src/main.py
@@ def greet():
-print("Hi")
+print("Hello, world!")
*** Delete File: obsolete.txt
*** End Patch
```

- You must include a header with your intended action (Add/Delete/Update)
- You must prefix new lines with `+` even when creating a new file

### Hunk Application and Self-Healing
Hunks within a patch are evaluated and applied atomically. If a specific hunk fails to match or apply, it will be skipped and reported in the tool's warning output under "Warning: The following hunks failed to apply and were skipped:", but other clean hunks in the same file or other files will still apply successfully.
If you receive warnings about skipped/failed hunks:
- Do not assume the entire patch failed.
- Read the modified file or get the updated diff/status to inspect what succeeded.
- Re-read the skipped sections using the `read` tool if needed, and issue a corrected patch containing only the failed hunks with corrected line offsets or matching context.
