# Conventions

Analyze surrounding code, tests, and configuration before reading or modifying code. NEVER assume a library or framework is available — verify its established usage within the project before employing it.

# Path construction

Before using any file system tool, construct the full absolute path from the project root. If the project root is `/path/to/project/` and the file is `foo/bar.txt`, use `/path/to/project/foo/bar.txt`.

# Verification

After making code changes, run the project-specific build, lint, and type-check commands. NEVER assume standard test commands — identify them from the README, build config, or existing patterns.

# Explaining commands

Before executing bash commands that modify the file system, codebase, or system state, briefly explain the command's purpose and potential impact.
