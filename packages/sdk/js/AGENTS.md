# SDK package guide

This package follows the root [AGENTS.md](../../../AGENTS.md) for general repo rules (style, testing, typecheck, technologies).

## Generated client structure

- v2: `src/v2/gen/client/client.gen.ts` / `types.gen.ts` — regenerated by `script/build.ts`.
- The old `src/gen/` generation and its hand-written client/server entrypoints
  are removed. The root `@opencode-ai/sdk` entrypoint re-exports `src/v2`.
- The generated V2 client still exposes both `client.v2.session.*` and the
  legacy-compatible `client.session.*` HTTP groups because the V1 session
  routes remain mounted until the deferred deletion pass. Use `client.v2` for
  new workspace consumers.

## Error handling contract

- `responseStyle: "fields"` (default): returns `{ data, error, request, response }`. `error` is `undefined` on success.
- `responseStyle: "data"`: returns `TData` on success, `TError` on failure. It does **not** return `undefined` on error.
- `throwOnError: true`: throws the parsed error body (wrapped by `wrapClientError` in `src/error-interceptor.ts`).
- `throwOnError: false` + `responseStyle: "data"`: returns the raw parsed error body, bypassing `wrapClientError`. The interceptor only fires on the `throwOnError: true` path.

## Generator limitations

- `@hey-api/openapi-ts` 0.99.0 does not support the `data`-style error return contract. The generated code returns `undefined` on error for `responseStyle: "data"`.
- The only way to fix generated client behavior is post-generation string patching in `script/build.ts`. Any fix to `client.gen.ts` or `types.gen.ts` must include a matching patch in the build script.

## Regenerating the SDK can break downstream typecheck — run the `opencode` gate

Regeneration has ripple effects beyond this package. Two examples: the client's `RequestResult` types `response`/`request` as **optional** (`response?: Response | undefined`) even under `responseStyle: "fields"` — so test/caller types that assume required `response` (e.g. `type SdkResult = { response: Response; ... }`) will fail typecheck. And adding new `Event`-union members (e.g. `message.part.updated.batch`) silently invalidates `@ts-expect-error` directives that guarded the *absence* of those events → `error TS2578: Unused '@ts-expect-error' directive`. Always `bun typecheck` from `packages/opencode` (which the pre-push hook also runs) after regenerating, and expect to update consumers.

## Test conventions

- Tests live in `packages/opencode/test/server/`, not in this package.
- SDK error-shape coverage: `packages/opencode/test/server/sdk-error-shape.test.ts`
  (uses `from "@opencode-ai/sdk/v2"`). Endpoint behavior tests belong under
  `packages/opencode/test/server/`; there is no separate generated-client test
  tree in this package.
- When testing `responseStyle: "data"` error returns, pass `responseStyle: "data"` as the second options argument (merged into `Config` at the top level), not inside `path`/`body`/`query`.
