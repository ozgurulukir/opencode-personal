Önce günlükleri ve birleştirilmiş yapılandırmayı inceleyin. Bu fork terminal arayüzünü, tarayıcı uygulamasını ve HTTP sunucusunu sürdürür. Kaynak projenin masaüstü uygulamasını derlemez veya dağıtmaz.

## Günlükler

Günlükler OpenCode veri dizininde saklanır:

- **macOS/Linux**: `~/.local/share/opencode/log/`
- **Windows**: `%USERPROFILE%\.local\share\opencode\log`

XDG ortam değişkenleri bu yolları değiştirebilir. Son on çalıştırmanın zaman damgalı günlükleri tutulur. Tanılama günlüklerini terminalde görüntülemek için:

```bash
opencode-personal --print-logs --log-level DEBUG
```

## Depolama

Varsayılan veri dizini `~/.local/share/opencode/` yoludur (Windows: `%USERPROFILE%\.local\share\opencode`). Sağlayıcı kimlik bilgilerini `auth.json`, günlükleri `log/` ve oturumları SQLite veritabanlarında saklar. Yayımlanan ikili dosyalar `opencode-personal.db` kullanır; kaynaktan derlemeler veritabanını derleme kanalına göre seçer. Yapılandırma ve kimlik bilgileri kaynak proje OpenCode ile paylaşılır.

Yedekleme veya sıfırlama öncesinde gerçek veritabanı yolunu inceleyin:

```bash
opencode-personal db path
```

`OPENCODE_DB` yolu geçersiz kılar. Göreli yollar veri dizinine göre çözülür. `OPENCODE_DISABLE_CHANNEL_DB=1` paylaşılan `opencode.db` dosyasını seçer. Veritabanını ve SQLite yardımcı dosyalarını sunucu durmuşken yedekleyin. Veri dizininin tamamını silmek, aynı dizini paylaşan diğer kurulumların kimlik bilgilerini ve oturumlarını da kaldırır.

## Yapılandırma ve eklentiler

Birleştirilmiş yapılandırmayı inceleyin:

```bash
opencode-personal debug config
```

Başlangıç veya araç hatalarını ayırt etmek için harici eklentiler olmadan çalıştırın:

```bash
opencode-personal --pure
```

`~/.config/opencode/opencode.json` veya `opencode.jsonc` içindeki genel yapılandırmayı, proje yapılandırmasını ve `.opencode/plugins/` ile `~/.config/opencode/plugins/` yerel eklenti dizinlerini kontrol edin. Sorunlu eklentiyi bulmak için eklentileri tek tek yeniden etkinleştirin. Boş bir `plugin` dizisi, yerel dizinlerden keşfedilen eklentileri tek başına devre dışı bırakmaz.

Keşfedilen beceri tanımlarını doğrulayın:

```bash
opencode-personal debug skill validate
```

## Sunucu ve tarayıcı bağlantısı

Fork'un sunucusunu başlatın ve yazdırdığı URL'ye bağlanın:

```bash
opencode-personal web --hostname 127.0.0.1 --port 4096
```

Yapılandırmanızdaki `server.hostname` ve `server.port` değerlerini kontrol edin veya CLI seçenekleriyle geçersiz kılın. HTTP Basic kimlik doğrulaması için `OPENCODE_SERVER_PASSWORD` ayarlayın; `OPENCODE_SERVER_USERNAME` varsayılan olarak `opencode` değerindedir. Ayrı bir tarayıcı istemcisi kullanıyorsanız tam origin değerini `--cors` ile ekleyin. [Sunucu](../server/) ve [Ağ](../network/) sayfalarına bakın.

`OPENCODE_DISABLE_EMBEDDED_WEB_UI=1` ayarlanmışsa gömülü tarayıcı arayüzü sunulmaz. Geliştirme tarayıcı uygulaması depo kökünden `bun run dev:web` ile ayrı olarak çalışır.

## Sağlayıcı ve model hataları

- Kimlik bilgileri süresi dolmuş veya reddedilmişse `/connect` komutunu yeniden çalıştırın.
- [Ağ](../network/) sayfasından sağlayıcı bağlantısını ve proxy ayarlarını kontrol edin.
- Model kimliklerini `providerID/modelID` biçiminde kullanın ve mevcut modelleri listeleyin:

```bash
opencode-personal models
```

`ProviderModelNotFoundError` için sağlayıcı ve model kimliklerini, `enabled_providers` ve `disabled_providers` ayarlarını kontrol edin. `ProviderInitError` için kayıtlı verileri değiştirmeden önce birleştirilmiş sağlayıcı yapılandırmasını inceleyin.

Sağlayıcı paketi veya önbellek hatalarında OpenCode'u durdurup önbellek dizinini yeniden adlandırın (varsayılan `~/.cache/opencode`; Windows: `%USERPROFILE%\.cache\opencode`). Yeniden oluşturmak için tekrar başlatın. Bu işlem araçların veya modellerin yeniden indirilmesini gerektirebilir; kurulu fork tarafından sabitlenen sürümleri güncellemez.

## Windows ve WSL

Yerel Windows ikili dosyaları desteklenir. Projenizin araçları Linux gerektiriyorsa [WSL](../windows-wsl/) de kullanılabilir. Sunucunun çalıştığı ortama ait yapılandırmayı, kimlik bilgilerini ve veritabanını kullanın.

## Linux panosu

Görüntü sunucunuza uygun bir pano aracı kurun:

```bash
# X11
apt install -y xclip
# or
apt install -y xsel

# Wayland
apt install -y wl-clipboard
```

Ekransız bir X11 ortamı için:

```bash
apt install -y xvfb
Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &
export DISPLAY=:99.0
```
