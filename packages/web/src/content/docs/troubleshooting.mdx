title: Troubleshooting
description: Diagnose problems with this fork's terminal, browser, and server.
---

Start with the logs and the resolved configuration. This fork maintains the terminal interface, browser app, and HTTP server. It does not build or distribute the upstream desktop app.

## Logs

Logs are stored under the OpenCode data directory:

- **macOS/Linux**: `~/.local/share/opencode/log/`
- **Windows**: `%USERPROFILE%\.local\share\opencode\log`

XDG environment variables can change these locations. Timestamped log files are retained for the ten most recent runs. To print diagnostic logs in the terminal:

```bash
opencode-personal --print-logs --log-level DEBUG
```

## Storage

The default data directory is `~/.local/share/opencode/` (Windows: `%USERPROFILE%\.local\share\opencode`). It contains provider credentials in `auth.json`, logs in `log/`, and SQLite session databases. Release binaries use `opencode-personal.db`; source builds choose the database by their build channel. Config and credentials are shared with upstream OpenCode.

Inspect the actual database path before backing up or resetting anything:

```bash
opencode-personal db path
```

`OPENCODE_DB` overrides the path. Relative paths resolve under the data directory. `OPENCODE_DISABLE_CHANNEL_DB=1` selects the shared `opencode.db` instead. Back up the database and its SQLite sidecar files with the server stopped. Deleting the entire data directory also removes credentials and sessions belonging to other installations that share it.

## Configuration and plugins

Inspect the merged configuration:

```bash
opencode-personal debug config
```

Run without external plugins to isolate startup or tool failures:

```bash
opencode-personal --pure
```

Check the global config at `~/.config/opencode/opencode.json` or `opencode.jsonc`, project config, and local plugin directories at `.opencode/plugins/` and `~/.config/opencode/plugins/`. Re-enable plugins individually to identify a failing one. An empty `plugin` array alone does not disable plugins discovered from local directories.

Validate discovered skill definitions:

```bash
opencode-personal debug skill validate
```

## Server and browser connection

Start the fork's server and connect to the URL it prints:

```bash
opencode-personal web --hostname 127.0.0.1 --port 4096
```

Check `server.hostname` and `server.port` in your config, or override them with CLI flags. Set `OPENCODE_SERVER_PASSWORD` for HTTP Basic authentication; `OPENCODE_SERVER_USERNAME` defaults to `opencode`. When using a separate browser client, add its exact origin with `--cors`. See [Server](../server/) and [Network](../network/).

If `OPENCODE_DISABLE_EMBEDDED_WEB_UI=1` is set, embedded browser UI serving is disabled. The development browser app runs separately with `bun run dev:web` from the repository root.

## Provider and model errors

- Run `/connect` again if credentials are expired or rejected.
- Check provider connectivity and proxy settings in [Network](../network/).
- Use `providerID/modelID` model identifiers and list available models:

```bash
opencode-personal models
```

For `ProviderModelNotFoundError`, check the provider ID, model ID, and any `enabled_providers` or `disabled_providers` settings. For `ProviderInitError`, inspect the resolved provider configuration before changing stored data.

For provider package or cache errors, stop OpenCode and rename its cache directory (default `~/.cache/opencode`; Windows: `%USERPROFILE%\.cache\opencode`). Restart to rebuild it. This can also require downloading tools or models again; it does not update versions pinned by the installed fork.

## Windows and WSL

Native Windows binaries are supported. [WSL](../windows-wsl/) is another option when your project's tools require Linux. Use the configuration, credentials, and database belonging to the environment where the server runs.

## Linux clipboard

Install a clipboard utility for your display server:

```bash
# X11
apt install -y xclip
# or
apt install -y xsel

# Wayland
apt install -y wl-clipboard
```

For a headless X11 environment:

```bash
apt install -y xvfb
Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &
export DISPLAY=:99.0
```

## Getting help

Search existing [fork issues](https://github.com/ozgurulukir/opencode-personal/issues), then include the fork version, operating system, reproduction steps, and relevant logs with credentials removed. Report vulnerabilities privately through [GitHub advisories](https://github.com/ozgurulukir/opencode-personal/security/advisories/new).
