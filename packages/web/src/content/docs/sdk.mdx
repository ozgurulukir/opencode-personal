The opencode JS/TS SDK provides a type-safe client for interacting with the server.
Use it to build integrations and control opencode programmatically.

[Learn more](../server/) about how the server works, or see the [extension points](../ecosystem/) available in this fork.

---

## Install

This page documents the SDK in `packages/sdk/js`. The npm package `@opencode-ai/sdk` belongs to upstream; do not assume it matches this fork's API contract. Install the fork workspace dependencies and use its local package:

```bash
git clone https://github.com/ozgurulukir/opencode-personal.git
cd opencode-personal
bun install
```

---

## Create client

`createOpencode()` and `createOpencodeServer()` launch the `opencode` executable on PATH; they do not automatically select `opencode-personal`. For the fork, start `opencode-personal serve --port 4096` yourself and use **Client only** below.

Create an instance of opencode:

```javascript
import { createOpencode } from "@opencode-ai/sdk"
const { client } = await createOpencode()
```

This starts both a server and a client

#### Options

| Option     | Type          | Description                    | Default     |
| ---------- | ------------- | ------------------------------ | ----------- |
| `hostname` | `string`      | Server hostname                | `127.0.0.1` |
| `port`     | `number`      | Server port                    | `4096`      |
| `signal`   | `AbortSignal` | Abort signal for cancellation  | `undefined` |
| `timeout`  | `number`      | Timeout in ms for server start | `5000`      |
| `config`   | `Config`      | Configuration object           | `{}`        |

---

## Config

You can pass a configuration object to customize behavior. The instance still picks up your `opencode.json`, but you can override or add configuration inline:

```javascript
import { createOpencode } from "@opencode-ai/sdk"
const opencode = await createOpencode({
    hostname: "127.0.0.1",
    port: 4096,
    config: {
        model: "anthropic/claude-3-5-sonnet-20241022",
    },
})
console.log(`Server running at ${opencode.server.url}`)
opencode.server.close()
```

## Client only

If you already have a running instance of opencode, you can create a client instance to connect to it:

```javascript
import { createOpencodeClient } from "@opencode-ai/sdk"
const client = createOpencodeClient({
    baseUrl: "http://localhost:4096",
})
```

#### Options

| Option          | Type       | Description                      | Default                 |
| --------------- | ---------- | -------------------------------- | ----------------------- |
| `baseUrl`       | `string`   | URL of the server                | `http://localhost:4096` |
| `fetch`         | `function` | Custom fetch implementation      | `globalThis.fetch`      |
| `parseAs`       | `string`   | Response parsing method          | `auto`                  |
| `responseStyle` | `string`   | Return style: `data` or `fields` | `fields`                |
| `throwOnError`  | `boolean`  | Throw errors instead of return   | `false`                 |

## Types

The SDK includes TypeScript definitions for all API types. Import them directly:

```typescript
import type { Session, Message, Part } from "@opencode-ai/sdk"
```

All types are generated from the server's OpenAPI specification and available in the <a href={typesUrl}>types file</a>.

## Errors

The default `responseStyle: "fields"` returns `{ data, error, request, response }`. With the default `throwOnError: false`, inspect `error` for HTTP failures. Examples below set `throwOnError: true` per call so HTTP failures throw and successful `data` can be read directly.

The SDK can throw errors that you can catch and handle:

```typescript
try {
    await client.session.get({ sessionID: "invalid-id" }, { throwOnError: true })
}
catch (error) {
    console.error("Failed to get session:", (error as Error).message)
}
```

## V2 session API (experimental)

SDK methods use flat parameters: `session.get({ sessionID })`, `session.prompt({ sessionID, parts })`, and `find.files({ query: "src", type: "file" })`. Do not wrap them in `path`, `body`, or nested `query` objects.

The root SDK export uses the generated V2 client. Its `client.v2.session` group
targets the `/api/session` routes and uses the V2 session and message types.
The unprefixed groups remain available for the compatibility API.

```typescript
const result = await client.v2.session.prompt({
    sessionID,
    prompt: { text: "Summarize the current session" }
}, { throwOnError: true })
console.log(result.data.assistant)
```

Use `client.v2.session.list()` and `client.v2.session.messages()` to read
sessions and their messages. V2 routes are experimental; see the server's
OpenAPI page at `/doc` for the full endpoint list and schemas.

## Structured Output

You can request structured JSON output from the model by specifying an `format` with a JSON schema. The model will use a `StructuredOutput` tool to return validated JSON matching your schema.

### Basic Usage

```typescript
const result = await client.session.prompt({
    sessionID: sessionId,
    parts: [{ type: "text", text: "Research Anthropic and provide company info" }],
    format: {
        type: "json_schema",
        schema: {
            type: "object",
            properties: {
                company: { type: "string", description: "Company name" },
                founded: { type: "number", description: "Year founded" },
                products: {
                    type: "array",
                    items: { type: "string" },
                    description: "Main products",
                },
            },
            required: ["company", "founded"],
        },
    }
}, { throwOnError: true })
// Access the structured output
console.log(result.data.info.structured)
// { company: "Anthropic", founded: 2021, products: ["Claude", "Claude API"] }
```

### Output Format Types

| Type          | Description                                            |
| ------------- | ------------------------------------------------------ |
| `text`        | Default. Standard text response (no structured output) |
| `json_schema` | Returns validated JSON matching the provided schema    |

### JSON Schema Format

When using `type: 'json_schema'`, provide:

| Field        | Type            | Description                                                |
| ------------ | --------------- | ---------------------------------------------------------- |
| `type`       | `'json_schema'` | Required. Specifies JSON schema mode                       |
| `schema`     | `object`        | Required. JSON Schema object defining the output structure |
| `retryCount` | `number`        | Optional. Number of validation retries (default: 2)        |

### Error Handling

If the model fails to produce valid structured output after all retries, the response will include a `StructuredOutputError`:

```typescript
if (result.data.info.error?.name === "StructuredOutputError") {
    console.error("Failed to produce structured output:", result.data.info.error.data.message)
    console.error("Attempts:", result.data.info.error.data.retries)
}
```

### Best Practices

1. **Provide clear descriptions** in your schema properties to help the model understand what data to extract
2. **Use `required`** to specify which fields must be present
3. **Keep schemas focused** - complex nested schemas may be harder for the model to fill correctly
4. **Set appropriate `retryCount`** - increase for complex schemas, decrease for simple ones

| ---------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `session.list()`                                           | List sessions                      | Returns <a href={typesUrl}><code>Session[]</code></a>                                                                                                                                                                    |
| `session.get({ sessionID })`                                    | Get session                        | Returns <a href={typesUrl}><code>Session</code></a>                                                                                                                                                                      |
| `session.children({ sessionID })`                               | List child sessions                | Returns <a href={typesUrl}><code>Session[]</code></a>                                                                                                                                                                    |
| `session.create({ ...parameters })`                                 | Create session                     | Returns <a href={typesUrl}><code>Session</code></a>                                                                                                                                                                      |
| `session.delete({ sessionID })`                                 | Delete session                     | Returns `boolean`                                                                                                                                                                                                        |
| `session.update({ sessionID, ...parameters })`                           | Update session properties          | Returns <a href={typesUrl}><code>Session</code></a>                                                                                                                                                                      |
| `session.init({ sessionID, ...parameters })`                             | Analyze app and create `AGENTS.md` | Returns `boolean`                                                                                                                                                                                                        |
| `session.abort({ sessionID })`                                  | Abort a running session            | Returns `boolean`                                                                                                                                                                                                        |
| `session.share({ sessionID })`                                  | Share session                      | Returns <a href={typesUrl}><code>Session</code></a>                                                                                                                                                                      |
| `session.unshare({ sessionID })`                                | Unshare session                    | Returns <a href={typesUrl}><code>Session</code></a>                                                                                                                                                                      |
| `session.summarize({ sessionID, ...parameters })`                        | Summarize session                  | Returns `boolean`                                                                                                                                                                                                        |
| `session.messages({ sessionID })`                               | List messages in a session         | Returns `{ info: `<a href={typesUrl}><code>Message</code></a>`, parts: `<a href={typesUrl}><code>Part[]</code></a>`}[]`                                                                                                  |
| `session.message({ sessionID })`                                | Get message details                | Returns `{ info: `<a href={typesUrl}><code>Message</code></a>`, parts: `<a href={typesUrl}><code>Part[]</code></a>`}`                                                                                                    |
| `session.prompt({ sessionID, ...parameters })`                           | Send prompt message                | `noReply: true` returns UserMessage (context only). | `session.command({ sessionID, ...parameters })`                          | Send command to session            | Returns `{ info: `<a href={typesUrl}><code>AssistantMessage</code></a>`, parts: `<a href={typesUrl}><code>Part[]</code></a>`}`                                                                                           |

---

#### Examples

```javascript
// Create and manage sessions
const session = await client.session.create({
    title: "My session"
}, { throwOnError: true })
const sessions = await client.session.list({}, { throwOnError: true })
// Send a prompt message
const result = await client.session.prompt({
    sessionID: session.data.id,
    model: { providerID: "anthropic", modelID: "claude-3-5-sonnet-20241022" },
    parts: [{ type: "text", text: "Hello!" }]
}, { throwOnError: true })
// Inject context without triggering AI response (useful for plugins)
await client.session.prompt({
    sessionID: session.data.id,
    noReply: true,
    parts: [{ type: "text", text: "You are a helpful assistant." }]
}, { throwOnError: true })
```

### Files

| Method                    | Description                        | Response                                                                                    |
| ------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------- |
| `find.text({ ...parameters })`    | Search for text in files           | Array of match objects with `path`, `lines`, `line_number`, `absolute_offset`, `submatches` |
| `find.files({ ...parameters })`   | Find files and directories by name | `string[]` (paths)                                                                          |
| `find.symbols({ ...parameters })` | Find workspace symbols             | <a href={typesUrl}><code>Symbol[]</code></a>                                                |
| `file.read({ ...parameters })`    | Read a file                        | `{ type: "raw" \| "patch", content: string }`                                               |
| `file.status({ ...parameters })` | Get status for tracked files       | <a href={typesUrl}><code>File[]</code></a>                                                  |

`find.files` supports a few optional query fields:

- `type`: `"file"` or `"directory"`
- `directory`: override the project root for the search
- `limit`: max results (1–200)

---

#### Examples

```javascript
// Search and read files
const textResults = await client.find.text({
    pattern: "function.*opencode"
}, { throwOnError: true })
const files = await client.find.files({
    query: "*.ts", type: "file"
}, { throwOnError: true })
const directories = await client.find.files({
    query: "packages", type: "directory", limit: 20
}, { throwOnError: true })
const content = await client.file.read({
    path: "src/index.ts"
}, { throwOnError: true })
```
