## Goal

## Steps

### Step 1: Fix `broken` Set → TTL-backed retry Map (`lsp.ts`)

**What:** Replace the permanent `Set<string>` blacklist with a `Map<string, { attempts: number; lastAttempt: number }>` that supports exponential backoff retry and automatic TTL eviction.

**Why:** A transient spawn failure (e.g., temporary filesystem issue, race with binary install) permanently disables an LSP server for the instance lifetime. After the transient condition resolves, the user must restart opencode to retry. A TTL + backoff allows automatic recovery.

**Files to change:** `packages/opencode/src/lsp/lsp.ts`

**Changes:**
 1. Add a module-level mutable config object:
     ```typescript
     export const brokenConfig = { ttl: 5 * 60_000, maxBackoff: 30_000 }
     ```
     Tests can mutate `brokenConfig.ttl` and `brokenConfig.maxBackoff` directly (ESM live bindings allow property mutation on exported objects).
 2. Change `State.broken` from `Set<string>` to `Map<string, { attempts: number; lastAttempt: number }>`.
 3. Add `backoffFor(attempts: number): number` returning `Math.min(1000 * 2 ** (attempts - 1), brokenConfig.maxBackoff)`.
    - With `attempts` starting at 1, this produces: 1s → 2s → 4s → 8s → 16s → 30s cap.
 4. Extract a shared helper:
    ```typescript
    const isInBackoff = (s: State, key: string): boolean => {
      const entry = s.broken.get(key)
      if (!entry) return false
      if (Date.now() - entry.lastAttempt > brokenConfig.ttl) {
        s.broken.delete(key)
        return false
      }
      return Date.now() - entry.lastAttempt < backoffFor(entry.attempts)
    }
    ```
 5. In `schedule()`:
    - On spawn/client failure: `s.broken.set(key, { attempts: (prev?.attempts ?? 0) + 1, lastAttempt: Date.now() })`
    - On success: `s.broken.delete(key)`
 6. Replace both `s.broken.has(root + server.id)` checks (in `getClients()` at line 278 and in `hasClients()` at line 352) with `isInBackoff(s, root + server.id)`.
 7. In the finalizer: `s.broken.clear()` still works on Map.

 **Test strategy:** Add tests in `test/lsp/index.test.ts`:
  - **Backoff retry test:** Mock `LSPServer.Typescript.spawn` to fail twice then succeed. Mutate `brokenConfig.ttl = 500` and `brokenConfig.maxBackoff = 50` for fast execution, restoring original values in `afterEach`. Call `hover` three times; the first two should trigger spawn failures and backoff, the third should succeed after the backoff expires. Uses real time because the backoff check uses `Date.now()` directly.
  - **TTL expiry test:** Mock `LSPServer.Typescript.spawn` to fail once. Call `hover` to record a failure, then advance time past `brokenConfig.ttl` (e.g., wait 600ms with `ttl=500`), then call `hover` again and assert it retries (spawn is called again).
  - **hasClients backoff test:** Mock a server whose `root()` throws on the first call, then succeeds. Call `hasClients` twice; the first should return `false` (server in backoff after root failure), the second should return `true` after backoff expires. This verifies `hasClients` uses the same `isInBackoff` helper as `getClients`.

### Step 2: Fix `notify.open` LRU eviction to use true LRU ordering (`client.ts`)

**What:** Track `lastUsed` timestamps in the `files` record and evict the least-recently-used file when `MAX_OPEN_FILES` is exceeded.

**Why:** `Object.keys(files)` returns keys in insertion order. A file opened once early and never used again evicts a recently-active file. True LRU ensures the most actively-used documents stay open.

**Files to change:** `packages/opencode/src/lsp/client.ts`

**Changes:**
1. Change the `files` record type from `Record<string, { version: number; text: string }>` to `Record<string, { version: number; text: string; lastUsed: number }>`.
2. In `notify.open`:
   - On existing file touch (`files[request.path] !== undefined`): update `files[request.path] = { version: next, text, lastUsed: Date.now() }`.
   - On new file open: `files[request.path] = { version: 0, text, lastUsed: Date.now() }`.
3. In the LRU eviction block inside `notify.open`:
   - Replace `const openPaths = Object.keys(files)` and `const oldest = openPaths[0]` with:
     ```typescript
     const sorted = Object.keys(files).sort(
       (a, b) => files[a].lastUsed - files[b].lastUsed,
     )
     const oldest = sorted[0]
     ```
4. In the `publishDiagnostics` eviction block: the existing code already sorts by `published.get(a)?.at`, which is a reasonable proxy for last-used. Keep as-is.

 **Test strategy:** Update `test/lsp/client.test.ts`:
 - Modify the existing `"notify.open LRU eviction cleans all four maps when files overflow"` test to verify true LRU:
   - Open file A, then open 49 additional unique files (B through 50, for a total of 50).
   - Touch file A again (update its `lastUsed`).
   - Open file 51 (triggers eviction because `openPaths.length >= MAX_OPEN_FILES`).
   - Assert file B (the true LRU, opened second and never touched) is evicted, not file A.
 - Add a new test `"notify.open LRU eviction uses lastUsed, not insertion order"` that explicitly opens files in a pattern where insertion order and LRU order diverge, then verifies the LRU candidate is evicted.

### Step 3: Fix `touchFile` to add observability for total failure (`lsp.ts`)

**What:** Keep `touchFile` non-failing (to preserve backward compatibility with 5 of 6 callers), but add granular per-client failure logging and a summary log when all clients fail.

**Why:** Callers have no indication that diagnostics were not refreshed. Partial failure (some clients succeed, some fail) is acceptable, but total failure should be visible in logs. Making `touchFile` fail would break `write`, `edit`, `apply_patch`, `lsp` tool, and `debug lsp` command, which do not pipe `Effect.ignore`.

**Files to change:** `packages/opencode/src/lsp/lsp.ts`

**Changes:**
1. Keep the public interface: `readonly touchFile: (input: string, diagnostics?: "document" | "full") => Effect.Effect<void>`.
2. Replace the `Effect.promise(() => Promise.all(...).catch(...))` pattern with `Effect.forEach`:
   ```typescript
   const touchFile = Effect.fn("LSP.touchFile")(function* (input: string, diagnostics?: "document" | "full") {
     log.info("touching file", { file: input })
     const clients = yield* getClients(input)
     if (!clients.length) return

     const results = yield* Effect.forEach(
       clients,
       (client) =>
         Effect.promise(() =>
           (async () => {
             const after = Date.now()
             const version = await client.notify.open({ path: input })
             if (!diagnostics) return { success: true as const }
             await client.waitForDiagnostics({
               path: input,
               version,
               mode: diagnostics,
               after,
             })
             return { success: true as const }
           })().catch((err) => {
             log.error("failed to touch file", { err, file: input })
             return { success: false as const }
           }),
       ),
       { concurrency: "unbounded" },
     )

     const failedCount = results.filter((r) => !r.success).length
     if (failedCount === clients.length) {
       log.error("all clients failed to touch file", { file: input, count: clients.length })
     }
   })
   ```
3. Do **not** introduce a new `LSPError` type. The non-failing behavior is preserved; observability is via structured logs only.

**Test strategy:** Add a test in `test/lsp/index.test.ts`:
- Mock a client whose `notify.open` throws.
- Call `touchFile` and assert it does **not** fail (returns `Effect.void`).
- Assert that the per-client error log and the "all clients failed" summary log are emitted.

### Step 4: Fix `hasClients` error handling (`lsp.ts`)

 **What:** Add `.catch()` on the `server.root()` promise so filesystem errors don't become defects and the style guide's "avoid try/catch" preference is respected.

 **Why:** `server.root()` can throw on filesystem errors. The current code has no error handling around `server.root()` at all — if it throws, the error becomes a defect because `Effect.promise` lacks a catch callback. `Effect.promise` turns rejected promises into typed failures (not defects), but without a catch callback the rejection propagates as a defect. Adding `.catch()` on the promise itself is cleaner than an inner `try/catch`.

**Files to change:** `packages/opencode/src/lsp/lsp.ts`

**Changes:**
 1. Replace:
    ```typescript
    yield* Effect.promise(async () => {
      const extension = path.parse(file).ext || file
      for (const server of Object.values(s.servers)) {
        if (server.extensions.length && !server.extensions.includes(extension)) continue
        const root = await server.root(file, ctx)
        if (!root) continue
        if (s.broken.has(root + server.id)) continue
        return true
      }
      return false
    })
    ```
    With:
    ```typescript
    yield* Effect.promise(async () => {
      const extension = path.parse(file).ext || file
      for (const server of Object.values(s.servers)) {
        if (server.extensions.length && !server.extensions.includes(extension)) continue
        const root = await server.root(file, ctx).catch((err) => {
          log.error("failed to resolve LSP root", { server: server.id, error: err })
          return undefined
        })
        if (!root) continue
        if (s.broken.has(root + server.id)) continue
        return true
      }
      return false
    })
    ```

 **Test strategy:** Add a test in `test/lsp/index.test.ts`:
 - Mock a server whose `root()` throws.
 - Call `hasClients` and assert it returns `false` (does not throw or defect).

### Step 5: No change needed for `callHierarchyRequest` duplication

**What:** The current `callHierarchyRequest` already preserves per-client item association by fetching `textDocument/prepareCallHierarchy` **per-client** inside the `run()` callback. The plan's proposed change (calling `prepareCallHierarchy` first and passing flattened items) would break this association.

**Why:** `prepareCallHierarchy` returns a flattened array across all clients. Passing `items[0]` from that flattened array to every client's `callHierarchy/incomingCalls` request would send the wrong item to most clients. The current implementation is correct.

**Files to change:** None.

**Changes:** None. The perceived duplication (calling `prepareCallHierarchy` then `incomingCalls`) only affects external callers who invoke both public methods in sequence. If this becomes a performance issue, a per-file cache can be added later without changing the per-client association contract.

**Test strategy:** No new test needed. Existing tests cover the per-client behavior.

---

### Step 6: Removed

**What:** The proposed `runAll` filter to exclude broken clients is a **no-op in practice**.

**Why:** `s.broken.add(key)` is only called in `schedule()` on spawn/client-creation failure. In those cases, the client is **NOT** pushed to `s.clients`. On success, the client is pushed to `s.clients` and `s.broken` is **NOT** modified. So under normal operation, a client in `s.clients` should never have its key in `s.broken`. The filter would never exclude anything. If post-init server crashes need to be handled, the correct fix is a process-exit handler or heartbeat check, not a `s.broken` filter.

**Files to change:** None.

## Architecture Decisions

### 1. TTL + Exponential Backoff for `broken` Map
**Chosen:** `Map<string, { attempts, lastAttempt }>` with 5-minute TTL and exponential backoff (1s → 2s → 4s → ... → 30s cap). Constants are exported as a mutable object `brokenConfig` so tests can mutate its properties for fast execution.  
**Alternatives considered:**
- Permanent Set cleared only on instance finalizer: too aggressive; transient failures during a long session would still block recovery.
- Unlimited retry on every call: risks rapid repeated spawn failures flooding logs and processes.
- Fixed retry count without TTL: stale entries still block forever after max retries exhausted.
- `Effect.TestClock` for time control: rejected because the backoff check uses `Date.now()` directly, and restructuring to use Effect time services would add unnecessary complexity.
**Trade-off:** The TTL ensures eventual recovery even if backoff is exhausted. The backoff prevents thundering herd. The Map preserves insertion-order iteration for cleanup. The mutable config object pattern works with ESM live bindings (property mutation is allowed; reassignment of exported bindings is not).

### 2. `lastUsed` Timestamp in `files` Record
**Chosen:** Add `lastUsed: number` (epoch millis) to each entry in the `files` record.  
**Alternatives considered:**
- Linked-list LRU: overkill for a 50-entry cap; adds complexity.
- Separate `Map<string, number>` for timestamps: extra indirection; the record is the SSOT.
**Trade-off:** A single timestamp field is minimal overhead and makes the eviction sort trivial.

### 3. `touchFile` Partial-Failure Semantics
**Chosen:** Log per-client failures, succeed if at least one client succeeds, log a summary if all clients fail. Do **not** change the `Effect<void>` return type or introduce a new error class.  
**Alternatives considered:**
- Fail on first error: too aggressive; one misbehaving client breaks diagnostics for all files.
- Fail when all clients fail: breaks 5 of 6 callers (`write`, `edit`, `apply_patch`, `lsp` tool, `debug lsp`) that do not handle the failure.
- Silently swallow all errors (current): hides total failure from operators.
**Trade-off:** Preserves backward compatibility while making total failure observable via structured logs. Callers remain unchanged.

### 4. `hasClients` Error Recovery
**Chosen:** Catch `server.root()` errors per-server via `.catch()` on the promise, log, and continue. Return `false` if no server succeeds.  
**Alternatives considered:**
- Let the error propagate as a defect: violates "no defects from expected filesystem errors."
- Fail the whole effect on first root error: one misconfigured server makes `hasClients` lie about others.
- Inner `try/catch` block: violates style guide preference for promise-level `.catch()`.
**Trade-off:** A false-negative (`false` when a working server exists) is safer than a defect for a read-only query.

### 5. `callHierarchyRequest` Per-Client Association
**Chosen:** Keep the current implementation unchanged. `callHierarchyRequest` fetches `prepareCallHierarchy` items per-client inside the `run()` callback.  
**Alternatives considered:**
- Fetch items once and pass flattened array: breaks per-client association (items from client A could be sent to client B).
- Inline per-client orchestration in `incomingCalls`/`outgoingCalls`: duplicates code without solving the external-caller duplication case.
**Trade-off:** The current code is correct and simple. External callers who need to avoid duplication can call `callHierarchyRequest` directly with pre-fetched per-client items if we expose that path later.

### 6. `runAll` Defensive Filtering (Removed)
**Chosen:** No filter added. `s.clients` and `s.broken` are mutually exclusive under normal operation.  
**Alternatives considered:**
- Filter `s.clients` in `runAll`: no-op in practice; adds dead code.
- Remove broken clients from `s.clients` immediately: risks race conditions with concurrent `getClients` pushes.
**Trade-off:** Simplicity. If post-init crashes need handling, add a heartbeat or process-exit handler rather than a stale-state filter.

## Open Questions

 1. **Backoff TTL configurability:** `brokenConfig.ttl` and `brokenConfig.maxBackoff` are properties on a mutable exported object, overridable in tests via property mutation. Should they be configurable via `Config` or environment variables for end users? For now they are constants on the object. If users in large monorepos hit repeated transient failures, a config knob may be needed.

2. **`touchFile` error type:** Resolved — no new error type is introduced. The non-failing behavior is preserved; observability is via structured logs only. No `LSPError` or `LSPTouchFileError` is needed.

3. **`runAll` vs `getClients` consistency:** Resolved — Step 6 is removed. No shared helper is needed.

 4. **Test timing for backoff:** Resolved — use real time with small mutable config object properties. Tests mutate `brokenConfig.maxBackoff = 50` and `brokenConfig.ttl = 500` for fast execution, then restore original values in `afterEach`. This avoids `Effect.TestClock` restructuring and keeps tests deterministic. The mutable object pattern is used instead of reassigning exported `let` bindings because ESM live bindings do not allow reassignment from importing modules.

5. **`files` record migration:** The `files` record is an internal implementation detail of `LSPClient.create`. Adding `lastUsed` is a non-breaking internal change. No migration needed.

## Breaking Changes / Migration Notes

- **None.** All public `Interface` methods retain their signatures.
- `touchFile` remains non-failing. Per-client failures are logged; total failure logs a summary. No callers need to change.
- `broken` changes from `Set<string>` to `Map<string, ...>` internally. No external consumers access `s.broken` directly (it is scoped to the `InstanceState` closure).
- `files` record gains a `lastUsed` field. No external code reads this record directly.
- Step 5 and Step 6 are removed; no behavioral changes.
